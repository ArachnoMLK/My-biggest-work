# KO bounds test — patch 11.00

Pin: **patch 11.00 / ABC SHA-256
`7d308423eaebcc82dfdda4ecc0e57d3abe78569534023aa7f9d776f626356db9`**. Method ids, obfuscated names
and offsets ("@N", as printed by `abc-disasm`) apply only to this ABC.

This page answers "where is the ring-out (blast-zone) test, and what exactly does it compare?". It is
**static bytecode evidence**: nothing was executed, and there is no runtime oracle. "[V]" means "the
bytecode has this shape", checked by `ko-verify`; "[H]" is an interpretation. No map values are
reproduced here; they live in the game's `LevelTypes` table.

## Reproduce

```text
python -I tools/bht.py abc-extract                    # sha256 must be the pin above
python -I tools/bht.py ko-verify                      # 147 anchors, 17 slot types
python -I tools/bht.py abc-disasm --method 3596       # _-h3U._-c5C, the test itself
python -I tools/bht.py abc-disasm --method 5275       # LevelType parser: LeftKill ... SoftTopKill
python -I tools/bht.py abc-disasm --method 5293       # level loader: CameraBounds -> _-I1f._-8I
python -I tools/bht.py abc-disasm --method 2984       # Entity._-8i, call @14346
python -I tools/bht.py abc-disasm --method 3138       # Entity._-eR, consumer of the mask
python -I tools/bht.py abc-find _-c5C --member        # #2984, #6290, #15192
python -I tools/bht.py abc-find _-a3D --member        # 7 methods
```

`tools/bh/ko.py` holds `ko_mask`, a line-by-line Python transcription of #3596, and the pins;
`tests/test_ko.py` pins its branch structure on made-up bounds.

## 2. The test `_-h3U._-c5C(x, y, exact, topAllowed)` #3596

It returns a `uint` mask: **1 = top, 2 = bottom, 4 = left, 8 = right**. With `cam` = CameraBounds
and `k` = the LevelType:

```text
if (exact || topAllowed) and y < cam.top - k.TopKill:    return 1          @34-69
lo = cam.left - k.LeftKill ; hi = k.RightKill + cam.right                  @70-100
if not exact:                                                              @102-181
    if k.SoftTopKill and y < cam.top - k.TopKill - 200:  return 1
    if not k.HardLeftKill:  lo -= 200
    if not k.HardRightKill: hi += 200
m = 0
if x < lo: m |= 4   elif x > hi: m |= 8                                    @188-222
if y > k.BottomKill + cam.bottom: m |= 2                                   @224-250
return m
```

| Claim | Status |
|---|---|
| All comparisons are strict (`ifnlt` / `ifngt` branch on the negation): a point exactly on a line is not out | [V] |
| The top test returns at once; when it fires, the side and bottom lines are not tested | [V] |
| The 200 margin applies only when `exact` is false, per side unless that side is `Hard`; the bottom line never gets a margin | [V] |
| With `exact` false and `topAllowed` false, the top line is crossed only with `SoftTopKill`, 200 further out | [V] |
| Left is tested before right and right only in the `else` branch, so at most one side bit is set | [V] |
| The 200 is a `pushdouble 200.0`; the kill distances are `uint` and the rectangle getters are `Number`, so the arithmetic is binary64 | [V] types; [H] no rounding issue for map-sized values |

So on 11.00 the **ring-out is detected in phase 5** (inside the movement monolith, after the position
writes in byte order) and **committed in phase 6** (`_-eR`). brawlhalla-sim (10.09) places "bounds,
ordinary KO #3040" in fighter pass 2; the two-step split here is consistent with that, but the mapping
of their passes to our phases is not checked [H].

## 4. Meaning of the two booleans

Both are **obfuscated booleans**: setters `_-q2W(v)` #2889 / `_-v2J(v)` #2907 store `_-W2b(v)` in a
`uint` (`_-H5X` / `_-j5M`), and the getters `_-5q()` #2931 / `_-wn()` #2949 return bit
`(field >>> 24) & 31` of that field. Read them as plain booleans.

| Claim | Where | Status |
|---|---|---|
| **`_-5q()` is the hitstun flag.** The hit application `_-26u._-76s` #1675 computes the stun in ms (`FixedStunTime` `_-7Z` or `_-T6p[phase]`, × 16, @1785–1824, local 41; or `_-7Z × 16` @198–203) and passes it to `_-26u._-L3f` #1670 (@229, @2565), which sets `target._-q2W(true)`, `_-u4B = t`, `_-v3y = stun` | #1675, #1670 @73–88 | [V] |
| It is cleared in `Entity._-Re(t, s)` #2981 when `!_-050()`, `_-u4B + _-v3y < t` and `s ≤ Entity._-Nj`; `_-8i` passes `s = v1D² + P5S²` (@205–285) and `_-Nj = 2500.0` (`_-y2E.init` #15351 @30077), i.e. speed ≤ 50 | #2981 @31–114 | [V]; [H] `_-050()` (not traced) |
| `Entity._-p1Y` #3034 (called by `_-eR` on a KO) resets it: `_-q2W(false)` @221 | #3034 | [V] |
| **`_-wn()` is "no collision line under the fighter".** `_-8i` stores the line returned by the collision query `_-CX._-X2e` (@3290 → local 17) in `_-96f` (`_-R15`) @3466, sets it to null @13127 on another path, and @13154–13169 sets `_-v2J(_-96f == null)` | #2984 | [V]; [H] "in the air" (a line can be a wall or a ceiling) |
| `_-p1Y` sets `_-v2J(true)` @193 on a KO; `_-y3M._-C2X` #7120 nulls `_-96f` and sets `_-v2J(true)` together | #3034, #7120 | [V] |
| `_-r51` (`uint`) is read or written by 38 methods, including `Jump`, `Dodge` and `IsDodgeLocked` | `abc-find _-r51 --member` | [V] count; meaning open |

So the KO test reads as:
- **in hitstun**: exact lines on all four sides, top included;
- **not in hitstun**: sides +200 unless `Hard`; top only while touching a line (or `_-r51 ≠ 0`), or with `SoftTopKill` 200 further out; bottom exact.

[H] This matches the player-known rule that you cannot be KO'd off the top without being hit.

## Limits

- Static only. Not shown: that phase 5 always runs `_-8i` for a fighter (#2991 selects behaviors by
  entity flags), the full KO commit (`_-p1Y`, scoring, lives) and its order against the hit pass
  #1665, the meaning of `_-r51` and `_-050()`, and of mask bits 16 and 32.
- No map values are given; a simulator reads them from `LevelTypes` / `LevelDesc` of the user's own
  install.
